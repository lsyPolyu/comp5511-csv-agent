### R01 目标、流程与边界

项目标题为 **A Data Analysis Agent with Execution Validation and Error Recovery**。面向学生及编程经验有限的用户，研究数据感知校验、结构化反馈和有界修复能否改善 CSV 分析任务成功率，以及增加的时间和模型用量成本。

流程为：上传单个 CSV → 查看摘要 → 输入英文问题并选择 `baseline`/`proposed` → 运行预定义工具 → 查看英文答案、表格、图表、动作日志和终止原因。第一版采用 Python、Streamlit、DeepSeek、Pandas、Matplotlib、Pydantic；具体版本和模型标识待官方文档核对及实际联调。

正式评测、生成答案、报告、slides和口头演讲保持英文；课程展示默认英文。2026-10-16用户明确授权P03展示补充：页面顶部提供English / 中文切换，默认English，选择仅在当前session保留。页面标题、说明、按钮、表单标签/帮助、摘要表头、状态及错误解释双语显示，技术选项可显示中文名称加原英文标识，内部key/枚举不变。原始CSV列名、类别值、数据、alias、ID、工具schema字段/枚举和错误码原样保留；工具原始错误消息保持英文，中文界面用本地静态映射提供解释并保留错误码与英文详情。用户与Codex的讨论、排错和讲解使用中文。

语言切换只更新展示，不重载CSV、不重跑统计/绘图，不改变dataset/run/result/chart ID或已生成PNG，不调用模型。控件选择及用户自填内容保留；新图表未自填的默认标题/轴标签随当前界面语言提供，用户再次明确生成才产生新图。中文图使用实际可用并经过缺字检查的本机字体。此补充仅便于中文操作和验收，不增加Agent中文问答、双语评测或正式实验配置。

平台边界：应用自有文案按上述约定翻译；锁定版Streamlit上传器内部Browse files/拖放提示无公开语言参数，保留原控件并提供中文标签和操作帮助。浏览器/操作系统原生对话框沿用其自身语言。不修改框架文件、伪替换DOM文字或升级依赖来隐藏此限制；实际浏览器行为单列验证边界。

第一版不增加 Agent 中文支持或双语实验，不训练模型，不执行任意生成代码。多模型/BYOK、登录、Excel、PDF、RAG、OCR、Hybrid Search/Rerank 等在课程版本稳定后另议；不自动增加组件消融实验。正式结论针对本次整体机制及固定英文评测范围。

## 2 数据与工具契约

### R02 CSV 加载

成功加载须得到不可被分析工具修改的原始表及新的 `dataset_id`。必须检查编码、表头、行结构、大小及行数限制；空文件、无数据、解析失败、空或重复列名、非 CSV 输入应返回可理解的英文错误，不能悄悄丢行、改列名或以旧数据代替本次失败输入。

工程默认D01：仅接受逗号分隔、带表头的 `.csv`（扩展名不区分大小写），编码为 UTF-8/UTF-8-BOM；上限20 MiB、100,000数据行。零字节、只有表头或仅空白行均拒绝。原列名保留大小写和首尾空格，空/全空格列名及完全重复列名拒绝。完整空白行可忽略，逗号构成的缺失记录仍是数据行。错误分别标识 `EMPTY_DATASET`、`CSV_PARSE_ERROR`、`INVALID_HEADER`、`INPUT_LIMIT_EXCEEDED`、`UNSUPPORTED_INPUT`。

### R03 数据摘要与 inspect_dataset

`inspect_dataset` 读取服务器绑定的当前数据上下文，第一版不允许模型任选其他会话的数据。无须业务参数；返回 `dataset_id`、`row_count`、列名和逻辑类型、每列 `missing_count`/`missing_ratio`、有限预览，以及有限类别样本和 `truncated` 标记。无当前数据时返回 `NO_DATASET`。

D01 默认预览最多5行、每列类别样本最多10项。缺失值输出 JSON `null`，不能输出字符串 `"nan"` 或非标准 JSON 数字。初始化时给两个版本相同摘要；程序在模型启动前准备摘要不计模型工具调用，模型显式请求 `inspect_dataset` 则计一次。

### R04 过滤与类型语义

`aggregate_data` 使用结构化 `filters`，每项为 `column`、`op`、`value`，支持 `eq/ne/gt/ge/lt/le/in`，不接受表达式字符串。D02 默认多个条件按 AND 组合，列名精确匹配，不隐式转换字符串与数字；`eq/ne/in`使用相同逻辑类型的值，null不是可比较值；`in`使用兼容值列表。第一版`gt/ge/lt/le`仅用于数值列和兼容数值，不隐式采用文本/日期字典序，非法类型返回 `INVALID_FILTER_TYPE`。

D02 默认只有空字段为缺失；`NA`、`N/A`、`null` 等非空文本不自动吞为缺失。至少有一个非缺失值且所有非缺失值均可明确解析为有限数字，才判为数值列；有文本混入时保留文本类型，不将脏值强转为缺失。整列全缺失时逻辑类型为`unknown`，可作row_count/count，但sum/mean返回`INCOMPATIBLE_AGGREGATION`，不依赖库的偶然dtype推断。默认不自动解析日期或将布尔值当可求和/平均的数值。

缺失值对上述过滤操作均不匹配，包括 `ne`；不增加隐含的“缺失不等于某值”规则。合法阈值或不存在的类别值导致零行时，返回真实空结果及 `EMPTY_RESULT` warning，不改阈值、不替换类别、不自动进入修复。两个版本使用相同规则。

### R05 聚合、缺失值、分组与排序

`aggregate_data` 的必要输入为：`filters`（可空）、`group_by`（可空列列表）、非空 `metrics` 列表及可选 `sort_by`。每个 metric 包含 `operation`、必要的 `column` 和唯一 `alias`；alias 不得与分组键冲突。D03 建议这些字段名作为统一契约。

| operation | 目标列与语义 | 空输入或组内全缺失 |
| --- | --- | --- |
| `row_count` | 无目标列，统计筛选后的行数，含其他列缺失的行 | `0` |
| `count` | 必须指定列，仅统计该列非缺失数量 | `0` |
| `sum` | 必须指定已确认为数值的列，忽略该列缺失值 | 数值列的空筛选/组内全缺失返回`null`，不伪造为0 |
| `mean` | 必须指定已确认为数值的列，以非缺失值数量为分母 | 数值列的空筛选/组内全缺失返回`null` |

`row_count` 明确区分行数与 `count(column)`，不增加新的分析算法。数值不兼容返回 `INCOMPATIBLE_AGGREGATION`，不能擅自改成另一种统计。

D02 默认保留缺失分组键，底层键为 `null`；界面缺失标签与同名真实字符串须能区分。无分组的空输入返回一行零计数/null指标；有分组的空输入返回零行。保留指标字段定义、`filtered_row_count=0` 及 warning，不能以失败代替合法空集。全缺失指标带 `NO_VALID_VALUES` warning。

排序仅作用于真实结果字段，方向为 `asc/desc`；D02 默认按分组键升序，无分组时保持单行。显式多键排序按列表顺序比较，升/降序均null末尾，并列稳定；不存在字段拒绝。展示舍入不改变底层数值和评分输入。

### R06 结果引用、文件切换与会话隔离

成功聚合返回 `result_id`、`dataset_id`、`run_id`、`filtered_row_count`、分组/指标字段及类型、`rows`、操作说明和 warnings；结果与原始表分离。只发布完整成功的结果，失败调用不生成伪结果或覆盖已有成功结果。

D03 默认 `result_id` 绑定 **session + dataset_id + run_id**。只能引用当前会话、当前数据和当前任务产生的真实结果；不存在或过期引用返回 `INVALID_RESULT_REFERENCE`，不得泄漏其他会话内容。

用户选择替换文件时，立即使旧运行上下文和可操作结果失效；新文件加载失败时页面处于“无可运行数据”状态，并显示失败，避免继续使用旧表。成功加载产生新 `dataset_id`。同一文件重新加载也视为新上下文。新问题创建新 `run_id` 并清除旧结果引用和模型对话；清除会话同时清数据、消息、结果和进行中的运行。不同会话互不读取数据、结果或凭据。

### R07 plot_result 与单位

必要输入为当前 `result_id`、`chart_type`（`bar/line`）、实际结果字段 `x/y`、非空可打印文本 `title/x_label/y_label`；展示补充允许中文标题/轴标签，正式英文任务与课程交付仍使用英文。工具schema字段/枚举保持不变，unit仍按下表约定。输出 `chart_id`、来源 `result_id`、图表产物、底层绘图数据、类型、字段、标签和以下格式元数据。原始数据标签仍原样保留。

| 参数 | 工程默认与共同校验 |
| --- | --- |
| `x_kind` | `category/numeric/date`；bar默认category，line默认numeric。line只允许numeric/date；numeric必须为有限数值，不将类别字符串隐式强转 |
| `date_format` | 仅x_kind=date时必填；第一版仅允许`%Y-%m-%d`，要求完整字符串严格匹配`YYYY-MM-DD`且为有效日历日期。其他x_kind不得提供该参数；不猜测日/月顺序、时区或混合格式 |
| `y_format` | `number/percent`，默认number；仅控制显示，不改底层值或重新统计 |
| `decimal_places` | 严格整数0–6，默认2；拒绝bool、负数和超范围值；只影响显示舍入 |
| `unit` | 显式单位元数据，默认`unknown`；`fraction`表示底层比例。percent必须配unit=fraction，y_label须明确含`(%)`或`(percent)`；number配fraction时不乘100。其他单位使用非空英文文本，不自动推断 |

字段组合错误返回共同的`INVALID_PLOT_FORMAT`；真实x/y数据、日期或数值不合法返回对应字段错误。baseline保留共享执行保护，proposed额外预检，格式语义和工具schema相同。元数据保留原始x、解析后的排序键、绘图顺序及全部格式参数，解析仅作用于绘图视图，不修改结果表。

绘图仅取真实结果，不接受模型自填数值，不隐式重新聚合或新增不存在的分类列。未知类型、无效引用/字段、非数值 y、没有可绘制数据时明确报错。标量结果若没有合适 x 字段，须先取得合适结果，不能暗造分类。

D04 默认：bar 保留结果顺序，null分类使用可区分于真实字符串的显示标签；line 按数值或显式日期格式解析后的 x 升序，null x、歧义日期或无法排序的文字 x 返回`INVALID_PLOT_X`。部分 null y 不补0，保留缺失位置及 warning；全 null 或零行返回 `NO_PLOTTABLE_DATA`。未知单位标为未知，不推断货币。

生还率底层0.75可用number/fraction显示`0.75`，英文y标签为`Survival rate (fraction)`；显式percent/fraction且decimal_places=2时显示`75.00%`、标签如`Survival rate (%)`，底层仍是0.75。不能猜测75代表0.75或重复缩放；比例不机械限制在0–1（其他指标可能超过100%），语义正确性仍由原题和评分判定。选择这些参数是为避免模型隐式日期猜测和单位转换，保持两版本及评分一致。

## 3 两版本边界与运行规则

### R08 共同参数检查与必要运行保护

两个版本使用相同工具名称、输入 schema、统计语义、输出基础结构和安全限制。都检查 JSON、必填项、参数类型、额外字段、operation/op枚举、工具白名单和结果所有权；工具执行时仍须防止非法列访问、不兼容计算、资源越界及异常数字输出。

D03 默认统一结果含 `success/data/error/warnings`，并能关联 `tool_call_id` 和当前上下文；成功时 `error=null`，失败时 `data=null`，错误至少含 `code/field/message`，并记录 `error_stage=schema/dataset_validation/execution`。已成功的其他调用结果保留，但不当作本次失败调用的结果。

未知工具、错误 JSON、缺参数、不支持的 operation 等属于该调用的真实失败，不是可忽略事件。原始异常/堆栈和密钥不直接暴露给模型或界面。

### R09 proposed 唯一预期增量

| 行为 | baseline | proposed |
| --- | --- | --- |
| 基础解析、schema、执行保护、上下文隔离 | 相同 | 相同 |
| 完整 dataset-aware 前置检查 | 不接入；工具仍安全失败 | 执行前检查当前列、dtype、过滤值兼容性、结果归属和绘图字段 |
| 错误信息 | 共同的最小结构化错误，首错终止 | 增加 `requested`、真实 `available_columns`、`allowed_operations` 或有限候选，并以对应 tool result反馈 |
| 模型纠错机会 | 0 | 最多2个修复响应 |

proposed 的候选反馈和前置 validator 必须独立于共享计算工具，不能把它们悄悄加到 baseline 的共享路径。无效调用在 proposed 不进入计算/绘图函数；baseline 可在共享执行保护处失败。两个版本都不得自动把 `gender` 改为 `Sex`、替换指标或引用参考答案。合法空筛选规则相同；差异聚焦校验、反馈及修复这一整体机制，不另给 proposed 更强模型或隐藏提示。

### R10 工具尝试、多工具响应与8次上限

每个任务独立计数，记 `T=tool_attempts`，初值0，上限8。

1. 对模型返回且协议有效的调用，按响应原顺序串行处理，不并行抢占预算。**进入每个调用的参数解析/校验之前先令 T+1**；初始调用、inspect、非法 JSON/参数、未知工具、预检/执行失败、修订后的再次调用均各计一次。
2. 一次模型响应包含多个调用时，每个实际尝试分别计数。读取程序准备的初始摘要、单纯模型文本及 API 网络重试不增加 T。
3. D05 默认两个版本在批内首个真实失败后均停止该批后续调用。未尝试项返回匹配各自 `tool_call_id` 的 `skipped_after_error`；不执行、不增加 T，也不作为新错误触发额外修复。baseline 随即终止；proposed 才可能开启下一修复响应。
4. T已为8时，剩余调用逐个关闭协议，标 `skipped_budget`，不执行第9次；这些占位回包不增加 T/R。若 T从7变8，批内后续调用亦同。**第8次恰失败时，剩余项以skipped_budget优先**，同时保留实际错误及first_error；proposed主终止原因为工具预算耗尽，baseline亦保留首错即停止的事实。
5. 缺失/重复 `tool_call_id` 等使响应无法可靠匹配时，按共同 `protocol_error` 终止，不执行其工具，也不凭空增加尝试数；需记录被拒绝响应的原因。

以上计数时点、批内中止和占位约定为D05工程默认细化。UI与日志须区分`attempted`和`skipped`，防止通过不计失败调用绕过8次上限。

### R11 错误反馈、2次修复与恢复

记 `R=repair_attempts`，初值0，整任务累计、不随恢复清零，上限2。baseline 固定R=0。

1. 初始失败使 T增加但不增加R。proposed 将该错误以原 `tool_call_id` 回传；仅在工具、模型和时间预算允许且R<2时启动修复。
2. D05 默认在错误后的下一次**逻辑模型请求启动时**令 R+1；它对应一个修复响应，内含多个工具仍只计一个R，但各自计T。该轮网络重试不重复计R。模型仅检查数据、仅返回文字/澄清或空响应，也已消耗该轮修复机会。
3. 仅 `inspect` 成功不能解除失败分析/绘图调用的待修复状态；下一逻辑请求仍是下一次修复。D05 默认以当前待修复工具的成功修订调用且本轮无新失败，解除工具错误状态；待修复工具是inspect时，其合法重试可以解除。`UNKNOWN_TOOL`可由合法白名单工具的成功修订调用替代，包括纠正误拼后的inspect。其他不相关成功不能清除待修复状态。
4. `first_error`永久保留首错历史，`pending_error`跟踪最近真实失败；对应工具成功后若后续plot失败，下一修复针对plot，不能被要求重做早先已成功的aggregate。解除工具错误不等于恢复原问题的正确答案；故障恢复率仍按R16独立核验原请求。
5. 第二个修复响应成功解除错误后，可在剩余T/模型/时间预算内继续普通流程，例如再绘图；不因R=2直接截断成功恢复。此后再失败，或第二个修复响应仍失败/仅检查数据未解决问题，则 `unresolved`、`repair_budget_exhausted`，不启动第三次修复。
6. 第8次工具失败时，即使R尚余也不能再启动工具修复，按工具预算终止。合法空结果和 warning 不触发修复，也不能改阈值凑答案。模型请求用户澄清时结束本次运行，不把用户新回答混为同一正式任务的额外修复。

材料已确认“只inspect也消耗一次修复”；第2–5项是后来细化且用户本轮同意推进的D05工程默认，不冒称这些操作化细节早已由原始intent规定。实现及正式冻结仍须验证该口径。

### R12 API 重试、无进展与终止

分别记录 `logical_model_requests`、`physical_api_attempts`、`api_retries`、T和R。一次逻辑模型请求的传输重试复用相同消息与请求配置，不重新执行已完成工具，也不增加T或第二次R；每次实际HTTP请求都计入物理次数和实际耗时/可取得的usage。

D06 默认每任务最多10次逻辑模型请求（含收尾），每逻辑请求最多2次网络重试，单次HTTP超时30秒、任务总时限300秒。仅对明确的暂时性网络/限流/服务失败有限重试，鉴权或请求配置错误直接结束；耗尽则 `api_error`，不能伪装为工具错误或触发Agent修复。实际错误分类和超时可行性待官方API及smoke验证，正式前两版本共同冻结。

总时限从用户提交任务、创建run时以单调时钟建立`deadline=start+MAX_RUN_SECONDS`，覆盖调度等待、模型请求、重试等待、工具处理和可选收尾，不随重试/修复重置。每次开始工作前计算`remaining`；没有剩余时间则timeout，不再发请求或执行工具。

- 每次HTTP的整体wall-clock预算为`min(HTTP_TIMEOUT_SECONDS, remaining)`，同时配置连接/读/写/池分项上限；分项timeout不代替整体请求监督。隐藏SDK/transport自动重试关闭，由适配器显式计数。
- 重试退避默认1秒、2秒；服务端Retry-After如有，则等待为两者较大值并记录。等待可被取消，最多等待到deadline，预算不足不得在超时后再请求。30秒请求限额不使剩余5秒变成可等30秒。
- 工具从调度、输入传送、实际执行到结果验收均消耗remaining；执行中也须可停止。不能仅让线程等待超时却留工具后台继续。达到deadline或取消后停止工具、回收资源、拒绝发布部分产物；已开始尝试计T，未开始项只skipped。Windows具体监督方式见plan，须用慢工具验证。
- 取消、超时或更换数据时，将run置不可逆终态并撤销其generation。任何HTTP/工具结果发布前，重新校验session/dataset/run/generation、active状态和deadline；迟到结果只记脱敏`late_response_discarded`，不注册result/chart、不执行它请求的工具、不重开任务、不改变终态或T/R。
- 日志区分模型响应到达/丢弃、任务结束和资源回收时间；清理开销不算继续成功完成任务的时间，不把实测elapsed裁成300秒。取消远程请求不保证服务端未计费，已知物理请求及usage照实保留，未知usage为null；API取消或timeout不触发Agent修复。

采用统一deadline是为使两个版本的30/300秒限制可比较，防止重试等待或阻塞工具绕过总时限；具体数值与取消延迟仍待实测。

无工具响应只作一次最终回答、`needs_clarification` 或无效响应终止处理，不自动反复发送“继续”。空响应/无有效协议为 `protocol_error`。达到模型或总时限后停止新工作，记录 `model_budget_exhausted`/`timeout` 并清理运行资源。

D06 允许工具预算耗尽时最多一次禁用tools的收尾请求，仍受模型和时间总上限约束，不执行新工具、不再修复，不能改变已有 `unresolved`/错误终止事实。若第8次成功且无待执行调用或待修复错误，可基于已有完整产物正常收尾，仍须R16评分，不能仅因达到8就造成功或失败。收尾请求仍返回tool calls则拒绝执行并记录协议错误。baseline 首错不发此额外请求。

### R13 最终展示与运行状态

最终展示包括英文答案、当前运行的真实表/图引用、warning、模式、模型、T/R/模型请求数、耗时、usage和终止原因。D03 建议最终结构含 `answer/result_ids/chart_ids/status/termination_reason`；`completed` 仅表示有相应证据的正常结束，不等于正式评分成功。尚未解决的真实失败、缺失图表或澄清不能被模型一句成功声明覆盖。

只引用本次真实产物；数值、表格和图表不一致或请求输出缺失，正式评分须失败。UI 显示部分结果时明确其为 partial，不补造完整答案。usage未知显示 `Unknown`/JSON null，不填0。

仅明确运行操作启动一次任务；运行中防止重复提交。普通 Streamlit rerun、展开日志、调整展示组件不得重复模型请求或扣费。文件切换、清除会话或取消运行后，迟到的旧响应不得重新写回新上下文。

### R14 密钥、白名单与离线模式

密钥仅由适当环境配置提供，不写源码、上传文件、日志、导出或报告，不回显；鉴权错误也脱敏。模型只能调用三个白名单工具，CSV单元格仅作数据处理，不能执行其中指令或代码。

无Key时真实模式不发送请求并显示 `API key required`，用户仍可明确选择 `Offline demo (FakeProvider)`。离线模式用脚本化模型响应驱动真实本地工具，日志标 `mode=offline`；不发网络请求，不伪造真实token/模型延迟，不标为真实联调或正式实验。真实模式失败不静默降级成离线成功。

正常演示不强制故障；故障演示单独开关、标签和日志，与自然任务结果隔离。真实故障演示也必须使用真实API响应，脚本化修复路径须标offline。
