## 2 已确认的目标与研究问题

项目标题沿用已提交 Proposal：**A Data Analysis Agent with Execution Validation and Error Recovery**。

首要目标是按照课程要求按时完成可运行系统、真实实验、英文报告、英文演示和代码交付，并能够说明个人贡献。理解代码也是目标，详细教学主要安排在阶段验收后。

目标用户是学生及编程经验有限、需要进行探索性数据分析的用户。系统将上传 CSV 后的自然语言问题转化为可核验的计算、表格和图表。

核心研究问题：数据感知校验、结构化错误反馈和有界修复组成的整体机制，能否提高任务成功率，以及带来多少延迟、模型调用和 token 用量成本。

研究允许 proposed 没有改善，或仅对部分任务有效。结论须反映实测结果、剩余语义错误和可靠性与成本之间的权衡。若需要区分各组件的独立增益，应另行说明新增消融设计的范围和影响。

## 3 已确认的第一版范围与用户流程

第一版使用 Python、Streamlit、DeepSeek、Pandas、Matplotlib、Pydantic。具体依赖版本和支持 tool calling 的模型标识，后续依据官方文档核对并实际验证。

用户流程：

1. 上传单个 CSV，查看数据预览、列名、类型和缺失值摘要。
2. 输入分析问题，选择 baseline 或 proposed 并运行。
3. 模型提出结构化工具调用，由本地预定义工具执行分析。
4. 展示计算答案、请求所需的表格或图表，以及可观察的操作日志。
5. 出错时按对应模式停止或反馈修复；超限或无法解决时说明终止原因和已有结果。

核心工具与能力：

| 工具 | 范围 |
| --- | --- |
| `inspect_dataset` | 数据列、dtype、行数、缺失统计和有限预览 |
| `aggregate_data` | 过滤、可选分组、count/sum/mean 及必要排序 |
| `plot_result` | 使用真实分析结果绘制 bar/line，并保留底层数据及标签 |

每任务处理一个 CSV，执行路径仅使用预定义白名单工具；不执行模型生成的任意 Python，不训练新语言模型。

baseline 遇到工具错误即停止。proposed 增加数据感知校验、结构化错误反馈及最多2次修复。两版本共同保留基础参数解析、结构检查、必要运行保护及异常处理。

每任务最多8次工具尝试，包含 inspect、失败和重试。修复机会按手册阶段8的口径落实：初始失败不计修复；错误反馈后开启一次修复响应计一次，即使仅重新检查数据也消耗机会；同一响应中的多次工具调用分别占用工具预算。具体协议在规格与实现中明确并验证。

### 第一版验收方向

- 新环境可按文档启动；真实 API、离线 FakeProvider 和演示模式有明确区分。
- 分析结果与手算样例及独立参考结果一致；原始数据保持完整。
- 图表检查底层数据、类型、轴字段、标题、标签和单位，不能只看图片外观。
- 正常路径、错误反馈、修复、修复失败及预算终止均有可复现案例。
- 更换文件或开始新任务时，旧数据上下文和结果不会被错误复用；会话数据隔离。
- 日志能够追溯工具名、参数、结果、失败、修复、调用计数和终止原因；不要求记录隐藏思维过程。
- 工具无报错不直接判为任务成功，最终输出须满足原始请求。

这些是待实现和待验收的标准，不是当前已经完成的能力。

## 5 已确认的实验框架与待落实计划

保留 Proposal 的研究约束，并按任务手册阶段10–11落实评测：

| 项目 | 计划 |
| --- | --- |
| 数据 | Titanic training CSV；UCI Bike Sharing daily CSV |
| 自然任务 | 各20题，共40个可回答的英文任务，覆盖过滤、分组统计、比较及图表 |
| 自然任务运行 | 40题 × 2个版本 × 3次重复，共240次 |
| 故障案例 | 10个固定列名或操作错误案例，两个版本使用相同注入位置和错误参数 |
| 故障运行 | 按手册阶段11，各案例每版本重复3次，共60次，独立报告 |
| 参考答案 | 独立脚本计算，不调用 Agent 分析工具生成参考结果；人工抽核代表性任务 |
| 成功判定 | 请求所需答案、表格和图表逐项核对；明确缺失值、count、分组、排序、单位和数值容差规则 |
| 指标 | 任务成功率、故障恢复率、median/p95 latency、工具尝试数、模型请求数、实际 token usage |

240次自然任务与60次故障运行是当前方案的计划规模，不是课程统一定额，也不是已经产生的结果。

两版本保持模型、参数、公共 prompt、工具定义、普通工具预算、题目及语言配置可比较；差异集中在额外校验、错误反馈和修复控制。每次运行重置会话，按任务与重复编号配对。开发题与正式评测题分开，参考答案不发送给模型。

正式运行前冻结数据文件和哈希、模型标识与参数、代码版本、题目、故障协议、prompt 和评分规则。API 失败及未完成运行的分母处理规则也须提前明确。保留逐次日志、失败类别、重复波动和未恢复案例；未知用量如实标为未知。

数值绝对容差暂采用手册建议的 `1e-6`，作为后续规格需要核对和冻结的默认值；Proposal 仅将该数值作为示例。其余具体任务、评分细则及数据处理语义也尚待落实。
